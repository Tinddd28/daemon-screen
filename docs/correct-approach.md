# Правильный путь решения

Как корректно захватывать экран под Wayland/X через DRM/KMS. Разбор ошибок
исходной реализации — в [mistakes.md](mistakes.md); устройство текущего рабочего
конвейера — в [pipeline.md](pipeline.md).

---

## 1. Модель прав — с этого всё начинается

Захват чужих фреймбуферов **принципиально требует привилегий**. `drmModeGetFB2`
обнуляет GEM-хендлы для всех, кроме DRM master и обладателей `CAP_SYS_ADMIN`.
Master держит композитор и не отдаёт (`drmSetMaster` → `EACCES`). Значит:

- «подобрать права из юзерспейса» нельзя — это by design ядра;
- рабочих варианта два:
  1. **`CAP_SYS_ADMIN`** (root или `setcap cap_sys_admin+ep` на бинарь) — читаем
     фреймбуферы, **не** становясь master, композитор продолжает работать;
  2. полноэкранный доступ из TTY, где вы сами master — не подходит для фонового
     агента.

Для целевого сценария (systemd-сервис) — вариант 1.

> **Важно:** нужен именно `CAP_SYS_ADMIN`, а не `drmSetMaster`. Отбирать master у
> композитора не надо и вредно — это сломало бы вывод на экран.

## 2. Архитектура: привилегии изолировать, а не размазывать

Наивно: «весь агент под root». Правильно (так сделано в
[gpu-screen-recorder](https://git.dec05eba.com/gpu-screen-recorder/about/) —
`gsr-kms-server`): **разделить на два процесса** и держать привилегии в
минимальном.

```
┌───────────────────────────┐        socketpair(AF_UNIX)         ┌──────────────────────────┐
│  ds-kms-server            │  ── dma-buf fd via SCM_RIGHTS ──▶  │  основной агент          │
│  привилегированный,       │  ◀── запрос «дай кадр» ──          │  непривилегированный     │
│  setcap cap_sys_admin+ep  │                                    │  EGL/GBM, кодек, сеть    │
│  только KMS: GetFB2,       │                                    │  (renderD128, без прав) │
│  PrimeHandleToFD           │                                    │                          │
└───────────────────────────┘                                    └──────────────────────────┘
```

- **`ds-kms-server`** делает ровно одно: открывает card-ноду, ставит клиентские
  капы, перечисляет plane'ы, `drmModeGetFB2`, `drmPrimeHandleToFD`, и передаёт
  dma-buf fd'шники + метаданные (`width/height/pitch/offset/fourcc/modifier`).
  Всё. Минимальная поверхность атаки для привилегированного кода.
- dma-buf fd передаётся между процессами через **`SCM_RIGHTS`** вспомогательного
  сообщения `sendmsg`/`recvmsg` на unix-сокете.
- **Основной процесс** — без привилегий: импорт dma-buf через EGL на render-ноде
  (см. pipeline.md), дальше кодек/сеть/логика DLP.

Плюсы: если основной процесс скомпрометирован — он без `CAP_SYS_ADMIN`;
привилегированная часть маленькая и легко аудируется.

> Текущий PoC для простоты держит обе половины в одном процессе (`ds-capture`
> под root). Это нормально для доказательства концепции; для боевого демона —
> вынести привилегированную часть по этой схеме.

## 3. Конвейер получения буфера (привилегированная часть)

Корректная последовательность (реализована в `src/kms.c`):

1. `open("/dev/dri/card*", O_RDONLY | O_CLOEXEC)` — **перебором**, не хардкодом.
2. `drmSetClientCap(DRM_CLIENT_CAP_UNIVERSAL_PLANES, 1)` — иначе не видно overlay/
   cursor-плоскостей.
3. `drmSetClientCap(DRM_CLIENT_CAP_ATOMIC, 1)` — нужно, чтобы у коннектора
   появилось свойство `CRTC_ID` (для маппинга plane→монитор).
4. `drmModeGetPlaneResources` → по каждому plane:
   - `drmModeGetPlane`; пропустить, если `fb_id == 0` (ничего не выводит);
   - определить тип (`Primary`/`Cursor`/`Overlay`) через свойства plane;
   - `drmModeGetFB2(fb_id)` → проверить `handles[0] != 0` (иначе нет привилегий —
     см. §1);
   - `drmPrimeHandleToFD` на каждый ненулевой handle → dma-buf fd;
   - сохранить `width/height`, `pitches[]`, `offsets[]`, `pixel_format` (fourcc),
     `modifier` (только если `flags & DRM_MODE_FB_MODIFIERS`).
5. **Освобождение** (частая ошибка): после экспорта закрыть GEM-хендлы
   (`drmCloseBufferHandle`) — dma-buf fd держит буфер сам; освободить `drmfb` и
   `plane`; в конце `drmModeFreePlaneResources`. fd'шники **не закрывать** — они
   уходят потребителю.

Дисциплина ресурсов: на **каждом** пути (успех и ошибка) освобождать `plane` и
`drmfb`; хендлы закрывать после экспорта; проверять границы массива результатов.

## 4. Конвейер пикселей (непривилегированная часть)

Кратко (детально — [pipeline.md](pipeline.md)):

dma-buf **нельзя `mmap`** — он тайленый/сжатый (AMD DCC) и в нестандартном
формате (XR30). Пиксели достаёт GPU:

1. headless EGL/GBM на **render-ноде** (`renderD128`, без прав);
2. `eglCreateImage(EGL_LINUX_DMA_BUF_EXT)` с fd/offset/pitch и **modifier**;
3. привязать к `GL_TEXTURE_EXTERNAL_OES`;
4. рендер в RGBA8 FBO → GPU делает detile + конвертацию формата;
5. `glReadPixels` → линейный RGBA8 → дальше PNG/кодек.

Модификатор передавать обязательно — иначе GPU не поймёт тайлинг.

## 5. Альтернатива: xdg-desktop-portal + PipeWire

Если цель — «просто скриншот на десктопе» без привилегий:
`org.freedesktop.portal.Screenshot` / `ScreenCast` + PipeWire.

- **Плюс:** ноль привилегий, работает под любым композитором, «правильный» путь
  с точки зрения Wayland-безопасности.
- **Минус:** требует **интерактивного согласия пользователя** (диалог портала).

Для тихого фонового DLP-агента это неприемлемо (потому в проекте и выбран путь
KMS+root). Но для интерактивного инструмента это более чистый и переносимый
вариант — стоит знать про развилку и осознанно её выбирать.

| | KMS + `CAP_SYS_ADMIN` | Portal + PipeWire |
|---|---|---|
| Права | нужен root/caps | не нужны |
| Согласие пользователя | не требуется | **требуется** (диалог) |
| Фоновый/тихий режим | да | нет |
| Переносимость между композиторами | зависит от KMS | высокая |
| Подходит для DLP-агента | да | нет |

## 6. Дорожная карта до боевого компонента

Что за рамками PoC (по возрастанию объёма):

1. **Вынести привилегированную часть** в `ds-kms-server` + `SCM_RIGHTS` (§2),
   `setcap cap_sys_admin+ep` вместо запуска всего под root.
2. **systemd-unit** для сервера (сокет-активация через `systemd.socket` — опрятно).
3. **Кадры вместо PNG:** вместо `glReadPixels`+PNG на каждый кадр — кодирование
   (VAAPI/NVENC или software) и стрим по LAN; PNG оставить как debug-выход.
4. **Мультиэкран/курсор:** композиция primary + cursor плоскостей по их
   `x/y/src_*` (метаданные уже собираются в `kms.c`).
5. **Надёжность:** переоткрытие при hotplug/смене режима, обработка отсутствия
   активного дисплея (DPMS off).

## Резюме «как правильно»

1. Признать, что захват требует привилегий — и дать `CAP_SYS_ADMIN`, **не**
   отбирая master.
2. Изолировать привилегии в маленький сервер, dma-buf передавать через
   `SCM_RIGHTS`.
3. Буфер брать через `GetFB2` + `PrimeHandleToFD`, аккуратно освобождая ресурсы.
4. Пиксели доставать GPU через EGL-импорт dma-buf (с модификатором), а не `mmap`.
5. Если привилегии/тихий режим не нужны — рассмотреть portal+PipeWire.
